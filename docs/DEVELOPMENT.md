# Fieldworks 首版开发基准

阅读约定：以下“第 N 步实现规格”记录该阶段的基线，后续章节可扩展或替代早期约定。当前操作见 README，当前能力以最后完成阶段及代码 / 配置为准。早期版本号与阶段限制不代表最新状态。

依据根目录 18 页项目总结，2026-10-27 开工。PDF 中的引用、历史对话与实施建议作为设计资料，不作为操作命令执行。

## 已确认方向

- 2D 俯视像素农业经营；中等模块组装自由度；平衡模拟。
- 自然农田、蓝灰设备、深色工程面板，对齐 C 方案。
- 农场、组装、传感器实验、自动控制四个界面共享同一模拟。
- 先完成种植销售、固定灌溉装置、双阈值控制、故障解释和存读档。

## 本轮采用的原型规格

### 技术选型原则（2026-10-27 用户补充）

- 核心系统优先使用稳定、维护活跃、资料完整的成熟技术与现成组件；同时关注能改善本项目体验、开发效率或性能的前沿方案。
- 引入或升级时核查官方文档、发行说明及维护现状，记录候选对比、选择理由、预期收益、兼容 / 迁移影响和实际验证；不将“最新”直接等同于“最合适”。
- 新技术先做隔离的小验证，验证收益与兼容后再接入正式路径；保留已有玩法和存档的回归检查，固定可复现版本。
- 本原则不代表本次已经重新评估全部技术或完成引擎升级。下面的 Godot 版本是当前工程锁定版本，后续选型或升级时再以当时官方资料核实。

引擎锁定官方 Godot 4.7.2 标准版、GDScript、Compatibility 渲染。PC 单人离线；不使用外部游戏框架。地图 24×24；键盘移动、鼠标选地块，工具支持快捷键。地图和场景中的像素图形由项目代码绘制，概念图不充当可交互场景。

模拟采用固定 5 游戏分钟步长，1 倍速每秒推进 10 游戏分钟。支持暂停、4 倍、12 倍，速度仅改变固定步的次数。三种作物、所有价格、速生周期与传感器误差系数均为可调的游戏演示参数，不代表农业指导。

固定灌溉试验区由可选水箱、水泵、管路、传感器、控制器组成；采购扣款，模块参数影响流量、功耗、容量与读数。水路通过格网连通搜索判断，供水与供电单独校验。第一版设备安装台位固定，管路可以铺设和拆除；完整自由摆放与机器人组装后续实现。

自动控制采用低于启动阈值开泵、达到停止阈值关泵、中间保持前态的滞回。默认 25% / 35% 均指土壤体积含水量演示值。可视化图必须接通传感器→判断→水泵，保护条件优先于控制输出。故障原因进入运行日志。

存档保存现有地块、时钟、库存、资金账、配置、管路、能源、传感器、自动规则 / 前态 / 日志、专项教学、作业计量与自主试验。当前第 6 版支持同引擎、对应参数一致的第 1～5 版导入，其他旧版本迁移另行核对。

## 验收重点

1. 三种作物能播种、生长、收获、出售；不能重复出售或透支采购。
2. 管路断开、缺水、断电、传感器失效、逻辑断线均阻止泵运行，修复后可恢复。
3. 双阈值中间保持前态，达到停止值关泵，加速与同量固定步结果一致。
4. 实验可比较真实含水量与读数，校准能改变农场中的同一测量链。
5. 存读档保留完整状态，坏档不会覆盖当前农场。

## 后续边界

机器人、温室、高级肥力 / EC / CO₂、订单、多农场、蓝图分享及完整科技树暂留后续。首版美术为程序绘制的可玩原型资产，尚未达到 PDF 成熟农场概念图的成品密度。

## 第 2 步实现规格

第 2 步验收时完成工程基础、地图、角色移动和地块检查，工具系统的后续实现见下一节。

- 地形数据使用 24×24 的统一格网；内部坐标 0～23，界面显示 1～24。
- 地图绘制基准为每格 32 个逻辑像素，显示时按容器尺寸等比缩放并居中。绘制和鼠标命中使用同一几何变换。
- 地形包括草地、道路、裸土、水域、农舍、树木、岩石和围栏；可通行与可耕属性由地形模型提供。
- 角色位置使用地块单位，速度为每秒 3.8 格，占地半径 0.22 格。分轴碰撞、最大 0.08 格的子步和单帧 0.25 秒上限防止穿墙与窗口卡顿后的跳跃。
- 农舍、水域、树木、岩石和边界不可通行。当前没有进入建筑、游泳或移除障碍的操作。
- WASD / 方向键移动；左键检查；G 切换网格；R 返回入口。角色位置与选中地块分别显示。
- 未引入作物、水分或资金占位数字。后续工具系统接入同一地形数据，避免界面与模型各维护一份状态。

## 第 3 步实现规格

- 每块地保存 `tilled`、`moisture` 与 `crop`；新播种的作物保存稳定种类 ID 和 `growth = 0`，自然生长的后续实现见第 5 步。
- 地形与耕作状态分开：草地开垦后保留原始地形信息，由地块状态驱动翻土后的土壤显示。
- 工具控制器先验证地图范围、1.6 格操作距离、途中障碍、地形、已有作物和所需资源，再修改地块。失败不触发资源消耗。
- 工具 ID 为 `inspect / hoe / sow / water / harvest`，成功与失败结果均提供稳定代码、文字、地块和是否变更的标记。
- 种子初始量为生菜 12、胡萝卜 8、番茄 6。采购和完整经营库存仍在第 6 步实现，当前这份数据会被后续系统沿用。
- 初始土壤体积含水量为 18%；浇水每次增加 12 个百分点并限制在 60% 以内。水壶最多使用 8 次，靠近池塘点击水面可补满。第 3 步时水分仅受人工操作改变，天气与蒸发的后续实现见第 4 步。
- 人工水壶每次浇水采用演示增量，不按实际升数换算。自然降雨在第 4 步加入等效土层换算，仍属于简化原型模型。
- 选中工具和种子的按钮状态、计数、地块检查及地图反馈绑定同一状态。右键只检查，避免检查时消耗当前工具资源。
- 收获接口验证 `growth >= 1` 后清空作物并计入农产品库存，保留翻土与水分。第 3 步使用测试夹具验证接口，第 5 步接入正常成熟过程。

## 第 4 步实现规格

### 时间、事件顺序与速度

- 初始绝对游戏分钟为 480（第 1 天 08:00）；固定步长 5 分钟，1× 下每 0.5 个真实秒处理一步。
- 真实帧时间先乘速度进入积压队列。每帧最多处理 64 步，多余时间保留；不会为了赶帧丢弃模拟事件。小于一步的余量也保留。
- 速度为 1 / 4 / 12，角色移动和输入不乘这个速度。暂停只阻止自然模拟及积压处理，不阻止手工操作；暂停期间不累加真实时间。
- 每步使用 `[开始时刻, 结束时刻)` 对应的天气计算水分，再进入结束时刻所属的新天气区段。`step_completed` 提供开始、结束、分钟数、区间天气与昼夜信息，后续系统读取这份上下文。
- UI 每批步进完成后刷新一次，手工操作仍立即刷新选中地块。渲染与降雨动画不决定农业模拟步数。

### 天气与水分原型

- 独立 `RandomNumberGenerator` 使用固定默认种子 `20261027`，每 360 游戏分钟抽取一个天气区段。
- 首日 00:00、06:00 区段为晴天，12:00 为小雨，以便验证蒸发与降雨方向；这些区段也消耗同样数量的随机抽样，之后按权重生成。
- 天气的降雨强度 / 白昼蒸发基准（mm/h）：晴 `0 / 1.6`、多云 `0 / 0.8`、小雨 `4.8 / 0.25`、阵雨 `8 / 0.12`。这些是游戏平衡参数。
- 等效土层厚度暂取 200 mm，入渗比例 0.85。每小时含水量增加量（百分点）为 `降雨强度 × 0.85 × 100 / 200`。
- 蒸发基准同样按等效土层换算；未翻土地块乘 0.7 覆盖系数，翻土地块乘 1；非白昼再乘 0.22。
- 超过原型田间持水阈值 35% 时，每小时排水为 `(含水量 - 35) × 0.18` 个百分点。
- 每个固定步的净变化为 `(入渗 - 蒸发 - 排水) × 5 / 60`，最后限制在 0～60%。只对可耕地计算，未加入真实土壤分层、径流和地下水模型。
- 白昼 06:00～18:00，黎明和暮色用于视觉过渡，夜间有轻微色调变化；水分模型与渲染使用同一个时钟。

### 运行状态与存档边界

- 运行快照保存时钟、未完成时间片、速度、暂停、天气区段及随机状态；随机种子和 64 位状态用十进制字符串经过 JSON，避免数值精度损失。
- 恢复前先检查两个子状态及日期 / 天气区段一致性，验证失败不替换当前状态。
- 该接口本身不写文件；第 7 步已将它与地块、角色、资源等一起接入持久保存，见下文存档规格。

## 第 5 步实现规格

### 统一配置与生长状态

- `data/crops.json` 保存顺序、名称、周期、干旱停长值、适宜区间、过湿停长值、夜间系数、耗水与收获数量。`crop_catalog.gd` 校验并加载，种子按钮、工具与模拟读取同一来源。
- 作物实例保存 `id`、`growth`（0～1）和 `age_minutes`（播种至成熟的历时，包含停长时间）；收获清空作物实例。
- 阶段阈值为 0 / 0.12 / 0.35 / 0.7 / 1.0，对应播种、发芽、生长、接近成熟、成熟。画面由实际进度决定，成熟进度限制为 1。
- 当前基准周期：生菜 360 分钟、胡萝卜 540 分钟、番茄 720 分钟，均为适宜水分下的白昼等效时间。

### 水分、昼夜与固定步顺序

- 停长范围为水分 ≤8% 或 ≥55%；适宜范围分别为生菜 24～38%、胡萝卜 20～34%、番茄 22～36%。
- 从干旱停长值到适宜下限，水分系数由 0 线性升到 1；适宜区间内为 1；适宜上限到过湿停长值线性降到 0。
- 夜间生长再乘 0.35；每步进度增加 `5 × 水分系数 × 昼夜系数 / 基准分钟数`。
- 每个固定步先计算自然水分及作物耗水，再按更新后的含水量推进生长，最后切换到结束时刻天气。步骤上下文保留该区间的天气。
- 生菜、胡萝卜、番茄白昼耗水基准分别为 0.35 / 0.28 / 0.4 mm/h，乘随进度由 0.2 增至 1 的大小系数、水分系数及夜间 0.22 系数，再按等效土层换算。
- 这些是平衡模拟的游戏参数，尚未引入真实品种、温度积算、营养或产量质量模型。

### 成熟、恢复与收获

- 水分胁迫可以恢复，不设永久枯死；成熟后停止继续生长和作物耗水，不自动腐烂，仍受自然土壤水分变化。
- 同一株作物只发出一次成熟事件。UI 提示、阶段进度和像素图形都从实际作物状态读取。
- 收获在完整校验后按配置数量入库，清空作物，保留土壤水分和翻土。当前每格 1 份，未加入多次采收或品质分级。
- 第 5 步提供收获库存，采购和出售随后在第 6 步接入，文件存档在第 7 步完成。运行恢复测试手动复原农田与环境，未作为文件存档功能。
- 后续导出试玩包时需要包含 `data/*.json` 配置文件，并验证打包后从资源路径读取正常。

## 第 6 步实现规格

### 资金、库存和配置

- `data/economy.json` 是初始资金、赠送种子、价格、补水费用和单次采购数量上限的来源。配置使用整数游戏币，加载时验证价格与数量。
- 初始资金 600；种子进价 6 / 10 / 14，农产品售价 18 / 30 / 46，补水费用 2。免费初始种子数量仍为 12 / 8 / 6。
- `FarmState` 保存现金、种子、农产品、零件库存、账本及下一个交易号；交易锁为运行时临时状态，不是经营资产。
- 第 6 步时零件库存初始为空，集市只出售种子并收购农产品；第 8 步起已有实际模块采购。

### 交易与现金口径

- 购买先检查品种、整数数量、余额和库存上限，再同时扣款和发货；出售先核对整篮库存，再同时扣库存与入账。
- 每次购买都会得到相应数量的种子。连续合法购买可逐笔成交；一次按钮激活只提交一次，重复出售空库存被拒绝。
- 种子采购时记支出，播种只扣种子。收获只入库，出售才形成收入。初始资金属于开场资金，不计入经营销售。
- 净现金流 = 销售收入 - 所有费用；当前现金 = 初始资金 + 净现金流。没有将剩余库存、设备资产或折旧混入利润口径。
- 补水在扣款与装满后才通知观察者；无钱或已满则资源与账本都不改变。固定费用与剩余次数无关，提前通过工具栏提示。
- 交易完成通知期间拒绝再次进入交易；失败通知同样防止递归。共享农场的交易锁保证多个调用入口使用相同保护。

### 账本与界面

- 初始资金和每笔交易记录稳定 ID、绝对游戏分钟、类别、描述、带正负号的金额、结余，以及商品数量与单价。
- 类别包括 `opening / seed_purchase / produce_sale / water`；`energy / equipment / maintenance` 为后续费用接口，本阶段不自动产生对应费用。
- 集市显示持有数量、买卖单价、结算回执、累计收入支出和净现金流。账本每页 30 笔，按新到旧展示，所有页可访问。
- 打开时记录原暂停状态并暂停自然模拟，同时禁止地图点击、工具快捷键与角色移动。B / Esc / 返回按钮关闭，恢复原暂停状态，速度保持不变。
- 第 7 步已连同库存、现金、交易编号和完整账本一起保存并验证。

## 第 7 步实现规格

本节记录农业版存档基础；第 8 步已扩展为第 2 版，具体兼容与工程字段见下一节。

### 完整状态与兼容边界

- `save_codec.gd` 负责快照、独立候选状态验证及应用；`save_service.gd` 负责文件和封装。恢复时更新同一 `FarmState` 实例，保留工具、模拟与控件的共享引用，随后统一发出刷新信号。
- 保存 24×24 地形和地块、作物 ID / 进度 / 历时、种子 / 农产品 / 零件库存、现金、水壶、完整账本及下个交易号；保存角色坐标、朝向、行走距离和选中地块、工具、种子、网格。
- 保存时钟绝对分钟、步数、速度、暂停及未处理余量，以及天气区段、类型、种子和随机状态。临时悬停、动画、交互锁和市场 / 确认弹窗不保存，读取后回到农场。
- `format=fieldworks-save`，`version=1`、`rules_revision=1`，记录保存 UTC 时间、精确引擎版本及解析后农业 / 经济配置的 SHA-256 指纹。当前要求版本与配置一致，不提供迁移。
- 主体作为 `payload_json` 字符串封装并计算 SHA-256。64 位浮点值编码为固定 16 位小写十六进制字节标记（`ieee754-le-hex`），不通过十进制 JSON 解析，确保跨进程恢复后后续模拟完全一致；天气的 64 位整数状态仍使用十进制字符串。只解码数据，不加载对象或脚本。

### 校验与落盘顺序

- 先检查文件大小（最多 16 MiB）、封装、版本、配置、校验和及 JSON，再在独立农场中校验数据；失败不改变当前农场。
- 地形必须与当前固定地图一致，地块数量与可耕属性有效；含水量有限且在 0～60%，作物进度在 0～1、历时不超出游戏时间，进度不超出历时允许范围。
- 库存为支持的稳定 ID 与整数数量，现金非负；账本最多 50,000 笔，按唯一连续 ID 和时间排序，初始资金、商品单价 / 数量 / 金额、每笔余额及最终现金相互一致。
- 农作物规则无死亡和丢弃，按赠送种子 + 已购种子 − 剩余种子 = 在田株数 + 累计收获株数核对资源；累计收获从未售库存及已售数量计算。第 7 步版本要求零件库存为空；第 8 步起设备另有采购 / 安装 / 备用数量守恒规则。
- 角色必须处于可站立位置、朝向合法；工具、选中地块、网格、速度、暂停、天气与日期区段一致；时钟分钟必须等于 `480 + 步数 × 5`。非有限数、损坏浮点编码、交易中间状态均拒绝。
- 保存先验证内存，写同目录临时文件、flush / close、回读完整验证，再把有效旧主档复制并替换 `.bak`，最后替换主档。损坏主档不会覆盖有效备份；失败返回明确原因并保留先前正式文件。未模拟断电或操作系统崩溃，不能将进程测试等同于掉电耐久性认证。

### 玩家流程与位置

### 水电与同一时间步

- 灌溉接在同一 5 分钟步的自然水分之前，随后自然入渗 / 蒸发 / 排水 / 作物耗水，再推进作物生长和天气。工程变更事件在完整模拟批次结束后发出，避免界面从中间状态保存。
- 额定请求水量 = `流量 × 步长 / 60`；每升耗能 = `功率 / 流量`。实际剂量取额定请求、土壤可接纳量、可用水和可用电支持水量的最小值。

- `48 L/h / 24 W` 每步供 4 L、用 2 Wh；`96 L/h / 60 W` 每步供 8 L、用 5 Wh。水或电耗尽时只供最后可支持的一部分，零余量后不继续供水；浮点末位小于 1e-9 归零。
- 缺少模块、断管、断电、空水箱、空电池或没有可浇地块都阻止供水和水电消耗。手动开关意图保留，恢复条件后可重新供水；当前不根据作物适宜水分停止。
- 水价 20 L / 币，电价 10 Wh / 币，补满按缺口向上取整；已满或余额不足不收费。新模块为空；更换保留不超新容量的资源，超出部分记为丢弃，不产生免费补给。
- 地块趋势将自然项与按下一步水电和配水份额估算的灌溉项相加，提示中列出分项。趋势属于当前条件预估，暂停时不推进；实际模拟仍按每步剂量与资源约束计算。

## 第 9 步实现规格

本节记录测量版基线；第 10 步已接通自动控制并升级存档，见下一节。

### 测量链与数据归属

- `data/sensor.json` / `sensor_catalog.gd` 为采样、土壤响应、安装偏移、器件偏差、噪声与量化参数来源。活动通道 ID 固定为 `soil-probe-01`；探头模块 `sensor_basic` 已开放，价格 40 币，采购、安装、拆回沿用实际零件库存和设备账目。
- `FarmState.sensor` 保存安装标记、0 起始坐标、信号连接、模拟故障、土壤 / 安装响应、校准增益 / 偏移、配置版本、采样序号、独立 RNG 种子 / 状态、最新记录与最近 180 条历史。只有一个活动通道，可以移动到任意可耕地；历史记录各自保留当时位置和配置。
- 真实值直接读取对应 `farm.plot_at(cell).moisture`。土壤响应选项只改变测量链，不修改真实水分、作物、水文、天气或水电资源。
- 理想电压为 `(0.5 + 真实含水量 × 0.04) × 土壤增益 + 土壤偏移 + 安装偏移 + 0.06 V 器件偏差`，再加独立均匀噪声 ±0.008 V，按 3.3 V / 4095 量化为 12 位 ADC。
- 土壤响应：壤土 `1 / 0 V`，砂土 `0.9 / +0.05 V`，黏土 `1.12 / +0.08 V`；安装偏移：接触良好 `0 V`，松动 `-0.16 V`，浅层 `+0.12 V`。这些是可解释的游戏参数，不是实际仪器或土壤标定数据。
- 出厂换算为 `(ADC 电压 - 0.5) / 0.04`；最终换算为 `出厂值 × 校准增益 + 校准偏移`。有效值仍可能带偏差，不能把有效性当作精度保证。

### 采样、校准和无效数据

- 周期采样接在每个 5 分钟步的灌溉、自然水分、作物和天气更新之后；对外事件在整个模拟批次结束后发布。暂停不会周期采样，显式“立即采样”不推进农场时间。
- 噪声使用独立 RNG，种子和 64 位状态为字符串；每次正常连通采样消耗一次抽样。断线 / 已设置故障不消耗噪声，人工采样频率不改变天气 RNG 或水分模拟。
- 增益允许 0.5～1.5，偏移 -20～20 个含水量百分点。单点参考校准保持增益，用最近有效采样计算偏移；参考值限 0～60%，若地块在采样后变化则要求先重新采样。无有效采样不能进行参考校准。
- 位置、安装、故障或校准变更增加配置版本并立即采样（未安装时只保存配置）；原历史不重算。单点校准主要改善参考点附近误差，不保证全量程准确。
- 断开信号没有 ADC 和换算数；模拟开路为 ADC 4095、短路为 0、卡住保留前次 ADC。这三类明确故障均无有效读数。正常模式的 ADC 饱和、换算越过 0～60% 以及超过两个采样间隔的记录也判为无效。
- `control_reading` 返回 `valid / value / reason / minute`，无效时 `value=null`，不会回填真实值、零值或上次的有效读数。当前只提供此接口，自动控制链留到第 10 步；模拟故障由玩家设置，不表示已自动识别任意未知真实故障。

### 测量台与历史图

- `sensor_panel.gd` 使用 I / 按钮打开，阻止地图操作，但保持当前游戏时间设置；空格与 12× 按钮控制整个农场。与临时暂停的集市和灌溉工作台不同，测量台可边运行边观察采样。
- UI 区分当前真实值、采样真实值、原始 V / ADC、出厂换算、有效读数、采样误差、时刻和配置版本。采购价格来自统一模块配置；修改坐标、条件和系数要显式应用，不把输入草稿当作已执行状态。
- `history_chart.gd` 只画实际历史：绿色采样真实值、浅黄有效读数、横轴游戏时间、纵轴体积含水量 %。无效读数留空，红叉放在坐标轴下；不在 0% 位置伪造测量点。
- 更换位置时断开真实值和读数连线；配置变化和无效样本处断开读数连线。悬停显示采样序号、时间、位置和状态。最多保留 180 条，周期采样约为 15 游戏小时，人工采样也占历史容量。

### 存档与兼容

- 第 3 版 `version=3 / rules_revision=3` 默认 `user://saves/farm-v3.json`，传感器配置加入指纹，沿用原位浮点编码、校验和、临时写入回读和有效备份。
- `sensor_snapshot.gd` 核对必需字段、坐标、配置、有限系数、随机状态、ADC / 电压 / 出厂换算 / 最终值与有效性之间的关系、原始响应可达范围、连续序号、非递减时间和配置版本、历史长度及最新记录一致性。历史中的已知故障可保存，异常结构和不可能数值不加载。
- 设备所有权核对增加已装探头；已购数量 = 备用数量 + 活动安装数量。拆回后历史仍保留，当前通道无效，且能够合法保存。

- 样杯已知含水量范围 0～60%，土壤 / 安装来自原探头配置；不改变农场地块、库存、水电、资金、时间或天气 / 探头 RNG。换响应条件重置当前参考点、验证和系数，历史已同步证明保留。
- A / B 均为正常连通、同条件的出厂换算样本；记录时重置增益 1、偏移 0，保留参考真实值与完整原始信号。B 必须在 A 后且参考差至少 10 个百分点。
- 求解 `gain=(truth_B-truth_A)/(factory_B-factory_A)`，`offset=truth_A-gain*factory_A`；仍遵守原探头增益 0.5～1.5、偏移 ±20 的限制，拒绝无效和非有限输入。
- 校准后对两参考值中点重新采样；序号和配置版本必须比两参考样本新，系数匹配求解值，绝对误差 ≤0.75 个百分点且比未校准改善 ≥0.75 个百分点，才允许同步。当前容差与间距来自 `data/learning_tasks.json`。
- 同步需要已安装、连通、无明确故障的真实探头。`apply_profile_calibration` 一次性设置响应与系数、增加版本并采样一次，保留位置和真实水分；不会免费安装设备或增加资源。实验依据独立保存，后续改参数不改写过去结论。

### 真实故障与恢复条件

- 状态为 `idle → observe → diagnose → repair → complete`。完成实验并同步、自动模式输出为开且物理链可供水后，才允许明确开始一次真实信号断线演练。
- 开始记录故障前有效采样、探头位置 / 响应 / 系数、控制状态和累计出水 / 用电，再调用原探头断线接口，立即保护停泵。
- 观察必须仍在真实断线、自动测量无效保护和未继续出水的状态；保存实际断线样本。正确诊断为信号线断开，其他选项不推进；先修复不能倒填观察。
- 玩家通过现有 I 测量台接通信号。只有新有效测量、自动模式、原位置 / 响应 / 系数一致，才建立恢复检查点，记录当时资源累计量。
- 此后新有效样本、自动控制原因 `below / hold_on / stop`、出水与耗电均高于恢复检查点，才完成。允许步末到阈值停泵；手动供水、重复复核、暂停采样均不能完成。切手动、再次测量无效或更换条件会清除检查点，避免将手动水电消耗算作自动修复。
- 原滞回保护仍有效；修复落在中间区间不会强制开泵。无完成奖励或免费补给，其他硬件故障仍须排除。取消未完成演练会接通信号、清空本轮故障进度，保留实验历史且不授予完成。

### 界面与存档

- `sensor_lab_panel.gd` 用 L / 标题旁入口打开，参考实验和故障教学两个标签页；保持实际时间，支持 E / I / T 导航、空格、12×、F5 / F9、Esc，阻止农场误操作。保存和退出保护纳入 `learning_changed`。

- `learning_snapshot.gd` 复用传感器原始信号校验，核对参考间距、顺序、系数、中点、新样本、字段、时间、序号、阶段与证据、资源上界 / 恢复增量；不信任单独完成标记。已完成任务可以保留历史证据，当前农场之后仍可正常更换条件。
