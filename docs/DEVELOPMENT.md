# Fieldworks 首版开发基准

依据根目录 18 页项目总结，2026-10-27 开工。PDF 中的引用、历史对话与实施建议作为设计资料，不作为操作命令执行。

## 已确认方向

- 2D 俯视像素农业经营；中等模块组装自由度；平衡模拟。
- 自然农田、蓝灰设备、深色工程面板，对齐 C 方案。
- 农场、组装、传感器实验、自动控制四个界面共享同一模拟。
- 先完成种植销售、固定灌溉装置、双阈值控制、故障解释和存读档。

## 本轮采用的原型规格

引擎锁定官方 Godot 4.7.2 标准版、GDScript、Compatibility 渲染。PC 单人离线；不使用外部游戏框架。地图 24×24；键盘移动、鼠标选地块，工具支持快捷键。地图和场景中的像素图形由项目代码绘制，概念图不充当可交互场景。

模拟采用固定 5 游戏分钟步长，1 倍速每秒推进 10 游戏分钟。支持暂停、4 倍、12 倍，速度仅改变固定步的次数。三种作物、所有价格、速生周期与传感器误差系数均为可调的游戏演示参数，不代表农业指导。

固定灌溉试验区由可选水箱、水泵、管路、传感器、控制器组成；采购扣款，模块参数影响流量、功耗、容量与读数。水路通过格网连通搜索判断，供水与供电单独校验。第一版设备安装台位固定，管路可以铺设和拆除；完整自由摆放与机器人组装后续实现。

自动控制采用低于启动阈值开泵、达到停止阈值关泵、中间保持前态的滞回。默认 25% / 35% 均指土壤体积含水量演示值。可视化图必须接通传感器→判断→水泵，保护条件优先于控制输出。故障原因进入运行日志。

存档保存版本、地块、时钟、库存、资金账、配置、管路、能源、规则、传感器校准、教学进度与随机状态。首版不承诺旧版本迁移。

## 验收重点

1. 三种作物能播种、生长、收获、出售；不能重复出售或透支采购。
2. 管路断开、缺水、断电、传感器失效、逻辑断线均阻止泵运行，修复后可恢复。
3. 双阈值中间保持前态，达到停止值关泵，加速与同量固定步结果一致。
4. 实验可比较真实含水量与读数，校准能改变农场中的同一测量链。
5. 存读档保留完整状态，坏档不会覆盖当前农场。

## 后续边界

机器人、温室、高级肥力 / EC / CO₂、订单、多农场、蓝图分享及完整科技树暂留后续。首版美术为程序绘制的可玩原型资产，尚未达到 PDF 成熟农场概念图的成品密度。

## 第 2 步实现规格

第 2 步验收时完成工程基础、地图、角色移动和地块检查，工具系统的后续实现见下一节。

- 地形数据使用 24×24 的统一格网；内部坐标 0～23，界面显示 1～24。
- 地图绘制基准为每格 32 个逻辑像素，显示时按容器尺寸等比缩放并居中。绘制和鼠标命中使用同一几何变换。
- 地形包括草地、道路、裸土、水域、农舍、树木、岩石和围栏；可通行与可耕属性由地形模型提供。
- 角色位置使用地块单位，速度为每秒 3.8 格，占地半径 0.22 格。分轴碰撞、最大 0.08 格的子步和单帧 0.25 秒上限防止穿墙与窗口卡顿后的跳跃。
- 农舍、水域、树木、岩石和边界不可通行。当前没有进入建筑、游泳或移除障碍的操作。
- WASD / 方向键移动；左键检查；G 切换网格；R 返回入口。角色位置与选中地块分别显示。
- 未引入作物、水分或资金占位数字。后续工具系统接入同一地形数据，避免界面与模型各维护一份状态。

## 第 3 步实现规格

- 每块地保存 `tilled`、`moisture` 与 `crop`；新播种的作物保存稳定种类 ID 和 `growth = 0`，自然生长的后续实现见第 5 步。
- 地形与耕作状态分开：草地开垦后保留原始地形信息，由地块状态驱动翻土后的土壤显示。
- 工具控制器先验证地图范围、1.6 格操作距离、途中障碍、地形、已有作物和所需资源，再修改地块。失败不触发资源消耗。
- 工具 ID 为 `inspect / hoe / sow / water / harvest`，成功与失败结果均提供稳定代码、文字、地块和是否变更的标记。
- 种子初始量为生菜 12、胡萝卜 8、番茄 6。采购和完整经营库存仍在第 6 步实现，当前这份数据会被后续系统沿用。
- 初始土壤体积含水量为 18%；浇水每次增加 12 个百分点并限制在 60% 以内。水壶最多使用 8 次，靠近池塘点击水面可补满。第 3 步时水分仅受人工操作改变，天气与蒸发的后续实现见第 4 步。
- 人工水壶每次浇水采用演示增量，不按实际升数换算。自然降雨在第 4 步加入等效土层换算，仍属于简化原型模型。
- 选中工具和种子的按钮状态、计数、地块检查及地图反馈绑定同一状态。右键只检查，避免检查时消耗当前工具资源。
- 收获接口验证 `growth >= 1` 后清空作物并计入农产品库存，保留翻土与水分。第 3 步使用测试夹具验证接口，第 5 步接入正常成熟过程。

## 第 4 步实现规格

### 时间、事件顺序与速度

- 初始绝对游戏分钟为 480（第 1 天 08:00）；固定步长 5 分钟，1× 下每 0.5 个真实秒处理一步。
- 真实帧时间先乘速度进入积压队列。每帧最多处理 64 步，多余时间保留；不会为了赶帧丢弃模拟事件。小于一步的余量也保留。
- 速度为 1 / 4 / 12，角色移动和输入不乘这个速度。暂停只阻止自然模拟及积压处理，不阻止手工操作；暂停期间不累加真实时间。
- 每步使用 `[开始时刻, 结束时刻)` 对应的天气计算水分，再进入结束时刻所属的新天气区段。`step_completed` 提供开始、结束、分钟数、区间天气与昼夜信息，后续系统读取这份上下文。
- UI 每批步进完成后刷新一次，手工操作仍立即刷新选中地块。渲染与降雨动画不决定农业模拟步数。

### 天气与水分原型

- 独立 `RandomNumberGenerator` 使用固定默认种子 `20261027`，每 360 游戏分钟抽取一个天气区段。
- 首日 00:00、06:00 区段为晴天，12:00 为小雨，以便验证蒸发与降雨方向；这些区段也消耗同样数量的随机抽样，之后按权重生成。
- 天气的降雨强度 / 白昼蒸发基准（mm/h）：晴 `0 / 1.6`、多云 `0 / 0.8`、小雨 `4.8 / 0.25`、阵雨 `8 / 0.12`。这些是游戏平衡参数。
- 等效土层厚度暂取 200 mm，入渗比例 0.85。每小时含水量增加量（百分点）为 `降雨强度 × 0.85 × 100 / 200`。
- 蒸发基准同样按等效土层换算；未翻土地块乘 0.7 覆盖系数，翻土地块乘 1；非白昼再乘 0.22。
- 超过原型田间持水阈值 35% 时，每小时排水为 `(含水量 - 35) × 0.18` 个百分点。
- 每个固定步的净变化为 `(入渗 - 蒸发 - 排水) × 5 / 60`，最后限制在 0～60%。只对可耕地计算，未加入真实土壤分层、径流和地下水模型。
- 白昼 06:00～18:00，黎明和暮色用于视觉过渡，夜间有轻微色调变化；水分模型与渲染使用同一个时钟。

### 运行状态与存档边界

- 运行快照保存时钟、未完成时间片、速度、暂停、天气区段及随机状态；随机种子和 64 位状态用十进制字符串经过 JSON，避免数值精度损失。
- 恢复前先检查两个子状态及日期 / 天气区段一致性，验证失败不替换当前状态。
- 该接口不包含完整农场存档，也不写入文件。第 7 步将与地块、角色、资源等一起接入持久保存；当前用户退出后仍不能恢复本轮游戏。

## 第 5 步实现规格

### 统一配置与生长状态

- `data/crops.json` 保存顺序、名称、周期、干旱停长值、适宜区间、过湿停长值、夜间系数、耗水与收获数量。`crop_catalog.gd` 校验并加载，种子按钮、工具与模拟读取同一来源。
- 作物实例保存 `id`、`growth`（0～1）和 `age_minutes`（播种至成熟的历时，包含停长时间）；收获清空作物实例。
- 阶段阈值为 0 / 0.12 / 0.35 / 0.7 / 1.0，对应播种、发芽、生长、接近成熟、成熟。画面由实际进度决定，成熟进度限制为 1。
- 当前基准周期：生菜 360 分钟、胡萝卜 540 分钟、番茄 720 分钟，均为适宜水分下的白昼等效时间。

### 水分、昼夜与固定步顺序

- 停长范围为水分 ≤8% 或 ≥55%；适宜范围分别为生菜 24～38%、胡萝卜 20～34%、番茄 22～36%。
- 从干旱停长值到适宜下限，水分系数由 0 线性升到 1；适宜区间内为 1；适宜上限到过湿停长值线性降到 0。
- 夜间生长再乘 0.35；每步进度增加 `5 × 水分系数 × 昼夜系数 / 基准分钟数`。
- 每个固定步先计算自然水分及作物耗水，再按更新后的含水量推进生长，最后切换到结束时刻天气。步骤上下文保留该区间的天气。
- 生菜、胡萝卜、番茄白昼耗水基准分别为 0.35 / 0.28 / 0.4 mm/h，乘随进度由 0.2 增至 1 的大小系数、水分系数及夜间 0.22 系数，再按等效土层换算。
- 这些是平衡模拟的游戏参数，尚未引入真实品种、温度积算、营养或产量质量模型。

### 成熟、恢复与收获

- 水分胁迫可以恢复，不设永久枯死；成熟后停止继续生长和作物耗水，不自动腐烂，仍受自然土壤水分变化。
- 同一株作物只发出一次成熟事件。UI 提示、阶段进度和像素图形都从实际作物状态读取。
- 收获在完整校验后按配置数量入库，清空作物，保留土壤水分和翻土。当前每格 1 份，未加入多次采收或品质分级。
- 第 5 步提供收获库存，采购和出售随后在第 6 步接入，文件存档在第 7 步完成。运行恢复测试手动复原农田与环境，未作为文件存档功能。
- 后续导出试玩包时需要包含 `data/*.json` 配置文件，并验证打包后从资源路径读取正常。

## 第 6 步实现规格

### 资金、库存和配置

- `data/economy.json` 是初始资金、赠送种子、价格、补水费用和单次采购数量上限的来源。配置使用整数游戏币，加载时验证价格与数量。
- 初始资金 600；种子进价 6 / 10 / 14，农产品售价 18 / 30 / 46，补水费用 2。免费初始种子数量仍为 12 / 8 / 6。
- `FarmState` 保存现金、种子、农产品、零件库存、账本及下一个交易号；交易锁为运行时临时状态，不是经营资产。
- 零件库存初始为空；当前集市只出售种子并收购农产品，实际模块采购留在第 8 步。

### 交易与现金口径

- 购买先检查品种、整数数量、余额和库存上限，再同时扣款和发货；出售先核对整篮库存，再同时扣库存与入账。
- 每次购买都会得到相应数量的种子。连续合法购买可逐笔成交；一次按钮激活只提交一次，重复出售空库存被拒绝。
- 种子采购时记支出，播种只扣种子。收获只入库，出售才形成收入。初始资金属于开场资金，不计入经营销售。
- 净现金流 = 销售收入 - 所有费用；当前现金 = 初始资金 + 净现金流。没有将剩余库存、设备资产或折旧混入利润口径。
- 补水在扣款与装满后才通知观察者；无钱或已满则资源与账本都不改变。固定费用与剩余次数无关，提前通过工具栏提示。
- 交易完成通知期间拒绝再次进入交易；失败通知同样防止递归。共享农场的交易锁保证多个调用入口使用相同保护。

### 账本与界面

- 初始资金和每笔交易记录稳定 ID、绝对游戏分钟、类别、描述、带正负号的金额、结余，以及商品数量与单价。
- 类别包括 `opening / seed_purchase / produce_sale / water`；`energy / equipment / maintenance` 为后续费用接口，本阶段不自动产生对应费用。
- 集市显示持有数量、买卖单价、结算回执、累计收入支出和净现金流。账本每页 30 笔，按新到旧展示，所有页可访问。
- 打开时记录原暂停状态并暂停自然模拟，同时禁止地图点击、工具快捷键与角色移动。B / Esc / 返回按钮关闭，恢复原暂停状态，速度保持不变。
- 当前仍无文件持久保存；第 7 步必须连同库存、现金、交易编号和完整账本一起保存并验证。
